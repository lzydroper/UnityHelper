# 一、项目目标

在12周内完成一套可本地部署、可演示、具备完整文档的独立游戏开发 AI 知识助手，实现从"原始文档"到"可对话知识库"的全流程落地，并通过量化评测验证系统在召回率、答案准确性、响应速度等维度的实际效果。

| **维度** | **关键指标** | **交付标准** | **验收方式** |
| --- | --- | --- | --- |
| 1\. 核心功能 | 系统可用性 | 完成 Open-WebUI + Dify 集成，核心问答流程 100% 跑通。 | 可以完整操作从上传文档到获取答案的流程。 |
|     | 知识库覆盖 | 完成 2-3 类 核心数据源入库；有效文档片段 ≥ 1,000 条。 | 检查 Dify 后台知识库统计截图；抽查文档内容质量。 |
|     | 多语言支持 | 支持 C# 代码块的识别、高亮渲染及基础 Lua 热更概念查询。 | 输入 C#/Lua 代码片段，检查系统是否正确高亮并回答。 |
| 2\. 性能精度 | 检索准确率 | 在 20 个 典型测试问题中，系统返回相关文档片段的比例 ≥ 70%。 | 提交《测试记录表》，展示 20 个问题的检索结果截图。 |

# 二、项目建设背景

## （一）用户痛点

**1.版本迭代的信息孤岛：**unity游戏引擎更新频繁，不同版本间许多接口不兼容，为开发者带来更换版本的麻烦

**2.长尾 Bug 的定位困难：**报错场景多，开发者往往需要花费大量精力寻找解决特定场景bug的帮助文档

**3.开发流的断层体验：**开发者在编写代码的过程中难免出错，将代码复制后发送给大语言模型，然后粘贴后者给出的修复后的代码，过程麻烦

**4.热更新的技术门槛：**部分开发者不会C#对应的xLua/toLua热更新写法，因为无法高效完成热更新

## （二）解决方案

针对上述痛点，本项目提出构建 **“Unity开发智能适配助手”。**

该助手基于 Open-WebUI + Dify 的开源协同生态，以检索增强生成技术为核心驱动。通过整合 Unity/Unreal 官方全量文档、GitHub 精选 Issue 库、xLua/toLua 热更新专项手册等多源异构数据，利用 Rerank算法提升检索精度。系统旨在打造一个了解项目代码、能够覆盖最新 API、可以辅助热更转换的垂直领域 AI 伙伴，助力独立开发者实现高效的代码迭代。

# 三、项目建设内容

## （一）技术架构建设

### 1.整体架构

整体采用前后端分离架构。Open-WebUI 作为用户交互入口，提供对话界面、历史记录、多模型切换等功能；Dify 作为后端引擎，负责知识库管理、RAG 检索流程、工作流节点编排及 API 对外暴露。

### 2.前端架构

在原生 Open-WebUI 基础上进行以下核心建设内容：

**\- 接口配置**：在 Open-WebUI 设置中填入 Dify 发布的 API Base URL 与 API Key，完成与后端工作流的挂载。

**\- 界面定制：**修改欢迎页文案、Logo、主题色，使其符合"游戏开发助手"的视觉定位。

**\- 功能配置：**开启代码高亮渲染（支持 C#、Lua、JavaScript 代码块语法着色）、启用 Markdown 渲染。

**\- 对话管理：**配置多会话历史记录，支持按项目 / 模块分类保存对话。

**\- 部署方式：**Docker 容器化本地部署，提供详细的启动说明文档。

### 3.后端架构

在Dify工作流模式下构建完整的 RAG 处理管道，进行以下核心建设内容：

#### （1）知识库接入

- 在 Dify 知识库模块导入所有预处理完毕的文档
- 配置向量化模型（使用 text-embedding-3-small 或本地 bge-m3 模型）
- 设置检索参数：Top-K 值、相似度阈值、最大 Token 限制
- 挂载相关知识库，如官方 API 文档库等

#### （2）代码错误诊断智能路由

- 使用 LLM 节点对输入内容进行意图识别，判断是否为"报错调试"类请求
- 若是报错请求，进一步分类错误类型（空引用 / 版本不兼容 / API 弃用 / 编译错误等）
- 根据错误类型选择对应的文档子集进行定向检索，提升召回相关性
- 若非报错请求，走常规语义检索路径

#### （3）多维混合检索

- **向量检索：**面向官方 API 文档，通过语义相似度匹配找到"意思相近"的文档片段，擅长处理自然语言模糊提问
- **关键词检索：**面向 GitHub Issues 与社区帖，通过精确关键词匹配找到"说法相同"的案例，擅长处理具体方法名、报错代码片段
- **Rerank 融合：**两路检索结果经 Rerank 重排序模型（使用 bge-reranker-v2-m3 或 Cohere Rerank API）合并取优，输出最终 Top-K 参考片段

#### （4）上下文代码感知

- 设计代码感知 Prompt 模板：将用户代码片段、检索到的文档内容、用户问题三者组合传入 LLM
- 输出格式要求 LLM 给出"针对你这段代码的具体修改建议"，而非通用文档摘要
- 支持多轮追问：保留上下文窗口，允许用户基于上一轮答案继续提问

## （二）知识库建设

### 1.数据源

|     |     |     |     |
| --- | --- | --- | --- |
| **数据源名称** | **内容范围** | **采集方式** | **预计文档量** |
| Unity 官方 API 文档 | Scripting API、Manual（聚焦 C# 部分） | 官网 HTML 导出 / PDF 下载 | 约 1500+ 页 |
| Unity 高频 Issues 精选 | Unity 论坛 / Stack Overflow 精华帖 | 手工筛选导出，约 200 条 | 约 200 条 |
| GitHub 精选开源实现 | 高 star Unity 开源项目 README 与 Wiki | GitHub API 爬取 | 约 80 份 |
| 自建报错案例集 | 团队手工整理的 C# / Lua 常见报错与解法 | 人工编写 | 约 100 条 |

### 2.文档预处理

**\- 格式转换：**将 HTML、PDF、Markdown 等格式统一转换为纯文本，使用 pymupdf 处理 PDF，html2text 处理 HTML 页面。

**\- 噪声清洗：**去除导航栏、页眉页脚、广告内容、重复段落，清除乱码与无效符号。

**\- 结构化标注：**为每个文档片段添加元数据标签，包括来源名称（unity_api / xlua / github_issue 等）、文档版本、页码范围、内容类别（API 说明 / 示例代码 / 报错案例）。

**\- 分块策略：**对比实验两种策略后选取最优方案（见第六章评测内容）；默认使用语义分块，目标 Chunk 长度 400～600 Token，重叠 50 Token。

**\- 代码片段处理：**保留代码块完整性，不在代码块中间切断；对代码片段单独标注编程语言类型（csharp / lua）。

**\- 质量抽检：**每类数据源随机抽取 5% 片段人工审核，确保清洗质量达标。

### 3.知识库版本管理

- 使用 Git 对原始数据文件进行版本控制，记录每次更新内容
- 在 Dify 内为不同引擎版本（Unity 2022 LTS / Unity 6）创建独立知识库，支持按版本切换检索
- 建立数据更新日志，记录每次知识库扩充的内容范围与文档数量

## （三）功能模块建设

### 1.问答功能

- **意图识别：**判断问题类别（API 查询 / 报错调试 / 概念解释 / 代码建议），选择对应检索路径。
- **混合检索：**激活向量检索 + 关键词检索双通道，获取 Top-15 候选文档片段。
- **Rerank 重排：**对候选片段进行相关性重排序，保留 Top-5 高质量片段
- **答案生成：**将问题 + 检索结果组合送入 LLM，生成语义通顺、内容准确的答案。
- **来源引用：**答案末尾附上参考来源列表，注明文档名称与章节，方便用户核查。

### 2.代码错误诊断

- **错误类型识别：**自动分类为空引用异常、类型转换错误、API 版本弃用、命名空间缺失、热更新绑定错误等 8 类常见错误。
- **定向文档定位：**根据错误类型，优先检索对应章节文档（如"API 弃用"类错误优先检索迁移指南）。
- **修复建议输出：**提供不少于 2 种可行的修复方案，说明各方案的适用场景与风险。
- **代码示例补充：**在修复建议中附上可直接参考的代码示例（C# 或 Lua）。

### 3.上下文代码感知

- **代码识别：**自动检测输入中的代码块内容，提取语言类型、关键 API 调用、潜在风险点。
- **定向检索：**将代码中的关键 API / 类名作为检索词，精确匹配官方文档的对应章节。
- **差距分析：**对比用户代码写法与文档最佳实践，指出具体改进建议，而非仅复述文档。
- **多轮追问支持：**保留最近 5 轮对话上下文，支持"那这个方法怎么改"等接续追问。

### 4.界面交互

- **代码高亮渲染：**支持 C#、Lua、JavaScript、ShaderLab 等语言的语法着色。
- **一键复制代码：**代码块右上角提供复制按钮。
- **会话管理：**支持按游戏项目或功能模块创建独立对话，历史记录可持久保存。
- **知识库切换：**在界面提供 Unity 版本选择器，切换后检索范围自动对应该版本文档。
- **响应速度指示：**界面显示检索耗时与生成耗时，方便调优参考。
