# 落地任务总览与 Dify 边界

## 一、验收目标

本阶段需要完成三项可验收成果：

1. 知识库构建阶段完成：从 Unity 官方文档、GitHub 和社区问答中获取约 1500+ 页官方文档，以及 200 条以上高频 Issues 数据。
2. 功能开发与 RAG 调优完成：产品能够根据用户提问，精准调用相关知识库内容，并输出带来源依据的回答。
3. 前后端接通：Open-WebUI 前端与 Dify 后端 API 完成接通，核心问答链路暂未发现明显错误。

## 二、任务拆分

| 编号 | 子任务 | 主要产出 | 是否需要 Dify |
| --- | --- | --- | --- |
| T1 | 数据源确认与采集配置 | 数据源清单、爬虫配置、采集范围说明 | 否 |
| T2 | Unity 官方文档采集 | 1500+ 条官方文档页面 JSONL、HTML 原始备份 | 否 |
| T3 | GitHub/社区 Issues 采集 | 200+ 条高频问题 JSONL | 否 |
| T4 | 文档清洗、分块与元数据标注 | Dify 可导入 Markdown、manifest 清单 | 否 |
| T5 | Dify 知识库搭建 | Unity 文档库、Issues 案例库、报错案例库 | 是 |
| T6 | Dify RAG 工作流调优 | 意图识别、混合检索、Rerank、回答 Prompt | 是 |
| T7 | Open-WebUI 前后端接通 | API Base URL、API Key、模型入口配置 | 部分需要 |
| T8 | 测试与验收记录 | 20 个典型问题、5 类报错、10 轮连续对话记录 | 部分需要 |

## 三、需要在 Dify 上完成的部分

1. 创建知识库：
   - `Unity_Official_Docs`
   - `Unity_Issues_Cases`
   - `Unity_Error_Cases`
   - 可选：按 Unity 2022 LTS、Unity 6 拆分版本知识库
2. 上传本地清洗后的 Markdown 文档。
3. 配置分段与索引：
   - 如果使用脚本分块结果，Dify 中选择较小的自动分段或关闭过度切分。
   - 嵌入模型建议使用 `text-embedding-3-small`、`bge-m3` 或课程环境可用的同类模型。
4. 配置检索参数：
   - Top-K 初始值：8 到 12
   - 相似度阈值初始值：0.35 到 0.45
   - Rerank：优先开启，候选取 15，最终保留 5
5. 搭建工作流：
   - 用户问题输入
   - 意图识别节点
   - 按意图选择知识库
   - 知识检索节点
   - Rerank 节点
   - 答案生成节点
   - 来源引用输出
6. 发布 API：
   - 记录 API Base URL
   - 记录应用 API Key
   - 提供给 Open-WebUI 或前端配置使用

## 四、不需要在 Dify 上完成的部分

1. 爬取 Unity 官方文档、GitHub Issues、StackOverflow 问答。
2. 原始数据落盘、HTML 备份、JSONL 存档。
3. 数据清洗、去重、元数据标注、Markdown 生成。
4. 数据质量报告与数量统计。
5. Open-WebUI 的界面主题、代码高亮、会话历史配置。
6. 本地脚本运行、GitHub Token 配置、数据更新日志维护。
7. 测试记录表、截图整理、项目报告材料撰写。

## 六、完成判定

1. `quality_report.py` 输出 Unity 文档数不少于 1500。
2. `quality_report.py` 输出 Issues 数不少于 200。
3. Dify 后台知识库统计截图可证明导入成功。
4. 20 个典型问题测试中，相关召回不少于 14 个。
5. Open-WebUI 可通过 Dify API 完成至少 10 轮连续问答，无明显报错。
