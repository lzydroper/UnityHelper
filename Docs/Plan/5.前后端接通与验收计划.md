# 前后端接通与验收计划

## 一、目标

完成 Open-WebUI 前端与 Dify 后端应用 API 的接通，确保用户能够在前端发起 Unity 开发问题，并获得来自 Dify RAG 工作流的回答。

## 二、需要在 Dify 完成的准备

1. 完成工作流应用发布。
2. 获取 API Base URL。
3. 获取应用 API Key。
4. 使用 Dify 自带调试窗口完成至少 5 个问题测试。
5. 确认知识库检索与答案生成节点均能正常运行。

## 三、需要在 Open-WebUI 或前端完成的配置

| 配置项 | 说明 |
| --- | --- |
| API Base URL | 填入 Dify 发布的接口地址 |
| API Key | 填入 Dify 应用密钥 |
| Markdown 渲染 | 开启 |
| 代码高亮 | 开启 C#、Lua、JavaScript、ShaderLab |
| 会话历史 | 开启，便于导出测试记录 |
| 欢迎文案 | 改为 Unity 开发智能适配助手相关描述 |

## 四、联调测试用例

| 编号 | 测试问题 | 期望结果 |
| --- | --- | --- |
| F1 | `Rigidbody.AddForce 怎么用？` | 调用官方 API 文档并给出示例 |
| F2 | `NullReferenceException 是什么原因？` | 调用 Issues 或错误案例库并给出排查步骤 |
| F3 | `旧版 Input.GetAxis 怎么迁移到新输入系统？` | 调用官方文档，说明迁移方向 |
| F4 | 粘贴一段 C# 代码并询问 bug | 回答中指出具体代码位置 |
| F5 | 连续追问 `那我应该怎么改？` | 能结合上一轮上下文继续回答 |

## 五、验收流程

1. 在 Dify 调试窗口验证工作流。
2. 在 Open-WebUI 中配置 Dify 接口。
3. 发送 F1 到 F5 五个基础问题。
4. 连续对话 10 轮，观察是否报错或断连。
5. 记录每轮响应时间，常规问答目标小于 30 秒。
6. 保存前端问答截图和 Dify 后台日志截图。

## 六、问题排查

| 现象 | 排查方向 |
| --- | --- |
| 前端无响应 | API Base URL、API Key、网络地址是否正确 |
| Dify 有回答但前端不显示 | 返回格式、模型映射、Open-WebUI 适配配置 |
| 回答无来源 | Dify Prompt 是否要求输出来源，检索节点变量是否传入 |
| 回答泛化 | 知识库召回是否为空，Top-K 和阈值是否过严 |
| 响应过慢 | 降低候选片段数，开启 Rerank 前后对比耗时 |

## 七、交付物

1. Open-WebUI 配置截图。
2. Dify API 发布截图。
3. 前端问答成功截图。
4. 10 轮连续对话测试记录。
5. 问题排查与修复记录。
