# GitHub 与社区 Issues 采集计划

## 一、目标

采集不少于 200 条 Unity 高频问题数据，覆盖报错调试、API 弃用、包管理、构建失败、输入系统、Addressables、Shader 编译等常见场景。

## 二、采集范围

| 来源 | 采集方式 | 价值 |
| --- | --- | --- |
| GitHub Issues | GitHub Search Issues API | 获取真实项目中的高频报错和解决讨论 |
| StackOverflow | Stack Exchange API | 获取投票较高、答案较完整的 Unity 问答 |
| 自建案例 | 团队人工整理 | 补足课程演示中必须覆盖的报错类型 |

## 三、执行步骤

1. 配置 GitHub Token，避免匿名接口频率过低：

```powershell
$env:GITHUB_TOKEN="your_token_here"
```

2. 检查 `config.local.json` 中 `issues.target_items` 不低于 `220`。
3. 运行采集脚本：

```powershell
python collect_issues.py --config config.local.json
```

4. 检查输出文件：

```text
Data/KnowledgeBase/raw/issues/issues.jsonl
```

5. 运行质量统计：

```powershell
python quality_report.py --root Data/KnowledgeBase
```

6. 生成高频问题分类统计：

```powershell
python issue_category_report.py --input Data/KnowledgeBase/raw/issues/issues.jsonl --output-dir Data/KnowledgeBase/reports
```

## 四、推荐查询词

| 类型 | 查询词 |
| --- | --- |
| 空引用 | `NullReferenceException`、`GetComponent returns null` |
| 对象销毁 | `MissingReferenceException`、`object has been destroyed` |
| 编译错误 | `CS0246 namespace could not be found` |
| API 弃用 | `obsolete API`、`Unity API deprecated` |
| 构建失败 | `IL2CPP build failed`、`Gradle build failed` |
| 包管理 | `Package Manager error`、`manifest json error` |
| 输入系统 | `InputSystem error`、`new input system not working` |
| Shader | `shader compile error`、`pink material` |

## 五、质量要求

| 检查项 | 标准 |
| --- | --- |
| 数据量 | 不少于 200 条有效问题 |
| 有效正文 | 单条正文不少于 120 字符 |
| 去重 | 按 URL 去重 |
| 可追溯 | 保留原始 URL、标题、来源、创建时间或更新时间 |
| 优先级 | 优先保留评论数高、投票高、已回答或已关闭的问题 |
| 解决信息 | GitHub Issues 需抓取精选解决评论；StackOverflow 需抓取采纳或高票答案 |

## 六、评论与答案质量策略

GitHub Issue 的有效解决方案经常出现在评论区，而不是 Issue 正文本身。采集脚本需要执行以下策略：

1. 先按标题、正文、标签、仓库名计算 Unity 相关性，过滤非 Unity 开发问题。
2. 对保留的 GitHub Issue 抓取评论首页和尾页，避免只得到问题描述。
3. 按维护者身份、点赞数、代码块、`fixed`、`workaround`、`resolved`、`root cause` 等关键词筛选高价值评论。
4. 将筛选出的评论写入 `Selected solution comments`，随 Issue 正文一起进入 Dify。
5. 对 StackOverflow 问题抓取采纳答案和高票答案，写入 `Selected answers`。

## 七、Dify 使用方式

该任务本身不在 Dify 内完成。采集完成后，将清洗后的 Markdown 导入 Dify 的 `Unity_Issues_Cases` 知识库，用于关键词检索和报错案例匹配。

## 八、交付物

1. `issues.jsonl` 原始问题数据。
2. 高频问题分类统计。
3. Dify 可导入的 Issues Markdown。
4. 200 条以上数据量证明截图或日志。
